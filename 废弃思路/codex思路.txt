### 第一步：先决定“最短可交易时间尺度”

看三个数字：

-|  |  |
|---|---|
|  | 30 只股票的**有效盘口事件速率中位数**约 0.264 次/秒，倒数约 3.8 秒。这个统计能复现 |
| 下单确认中位数 262 ms、p99 741 ms | 能复现，共 199 个样本；这是券商状态确认耗时 |
| 撤单再挂至少 430 ms | 是把撤单和下单的中位数相加得到的粗估，**不能称为实测下限** |
- 下单确认中位数 **262 ms，p99 741 ms**
- 撤单再挂至少约 **430 ms**

所以你不应该从“我想做 HFT”出发，而应该规定：

> **策略持有周期至少要显著大于行情陈旧时间和执行延迟。**

我会给你目前系统这样的分级：

| 预测/持有周期 | 当前适合度 |
|---|---|
| 10–100ms | ❌ |
| 100–500ms | ❌ |
| 1–5秒 | ❌ |
| 5–30秒 | ⚠️ 需要 Tick-by-Tick |
| **30秒–2分钟** | ✅ 可研究 |
| **2–10分钟** | **✅ 主战场** |
| 10–60分钟 | ✅ |
| 数小时～几天 | ✅ |

IBKR API 本身支持 `Last / AllLast / BidAsk / MidPoint` 的 Tick-by-Tick 数据，但同时订阅数量受到 market-data-line 限制；官方目前规定 Tick-by-Tick 同时订阅上限约为账户 market-data lines 的 5%。:chatgpt-content-reference{index="0"}

## 第二步：用交易成本决定“策略必须赚多少”

这是最重要的一步。

你当前 Fixed：

```text
佣金买入       ≈ 8 bps
佣金卖出       ≈ 8 bps
中位点差       ≈ 7.6 bps
----------------------
基础往返成本   ≈ 23.6 bps
```

IBKR 官方目前日本股票：

- Fixed：0.08%
- Tiered 第一档：0.05%
- 最低 ¥80/单 :chatgpt-content-reference{index="1"}

Tiered 在 TSE Prime 还包括约：

- Exchange：0.002%
- Clearing：0.0007%
- Access：¥2.70/order :chatgpt-content-reference{index="2"}

因此你的策略不应该问：

> “未来会上涨吗？”

而应该问：

> **“未来预期上涨幅度是否足以覆盖成本，并且还留下足够利润？”**

我会给策略设置：

```text
Expected Alpha
>
Commission
+ Spread
+ Slippage
+ Adverse Selection
+ Safety Margin
```

例如 Fixed 环境综合成本约 25–30bps，那么我不会因为模型预测：

```text
+18bps
+25bps
+30bps
```

就交易。

比较合理的开仓门槛可能是：

**预测 40–60bps 以上**

再根据实际回测优化。

# 第三步：计算每种策略的 Alpha Half-Life

这是判断策略类型非常有效的指标。

假设出现一个信号：

```text
T0 = 信号发生

未来：
5s     +8bps
10s    +13bps
30s    +28bps
60s    +42bps
120s   +55bps
300s   +61bps
600s   +40bps
```

这种信号非常适合 IBKR。

因为最佳收益发生在：

**2～5分钟**

而不是 100ms。

相反，如果：

```text
100ms  +10bps
500ms  +15bps
1s     +18bps
5s     +3bps
30s    0bps
```

即使这是一个非常优秀的 HFT 信号：

> **对你的 IBKR 系统也没有价值。**

因为在你的订单到达之前，Alpha 已经消失。

因此建议你以后每个策略都画：

```text
Expected Return
     ↑
     │
60bp │             ●
     │          ●     ●
40bp │       ●
     │
20bp │    ●
     │ ●
 0   └─────────────────→
    5s 30s 1m 2m 5m 10m
```

找到策略自己的：

**Alpha decay curve**。

# 第六步：每个策略必须过这 7 个指标

以后 Codex 每开发一个策略，我建议自动输出：

| 指标 | 必须回答的问题 |
|---|---|
| Gross Alpha | 信号产生多少bps？ |
| Net Alpha | 扣成本剩多少？ |
| Hit Rate | 胜率多少？ |
| MFE | 最大有利波动多少？ |
| MAE | 最大不利波动多少？ |
| Alpha Half-Life | Edge多久消失？ |
| Capacity | 一天能做多少钱？ |

此外还有两个对你尤其重要：

### Turnover

假设：

```text
单次净Edge = 12bps
每天交易 = 50次
```

可能非常差。

但是：

```text
单次净Edge = 70bps
每天交易 = 3次
```

可能反而非常优秀。

---

### Fill Probability

特别是你以后如果尝试 Maker：

```text
Signal = +50bps
```

并不意味着你能赚50bps。

如果：

```text
挂Bid成交概率 20%
```

实际策略完全不同。

所以需要记录：

```text
signal_price
limit_price
fill_price
fill_delay
fill_probability
cancel_time
post_fill_return
```
