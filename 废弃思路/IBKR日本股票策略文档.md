# IBKR 日本股票自动化交易策略文档

整理日期：2026 年 10 月 1 日，日本时间。用途：确定研究方向、定义首版策略，以及规定从回测到小额实盘的准入条件。

本文基于《claude思路》《codex思路》《策略汇总》整理，并补充 IBKR、IBSJ 和 JPX 官方规则。三份原稿作为参考材料处理；其中的开发邀约、程序指令和示例参数不自动成为本次执行要求或实盘配置。

版本：v3 整合版。本文合并初版的证据、成本和交易安全规范，以及补充版的策略目录、数据调度、评估模板和运维清单。所有首版必需能力与后续研究选项分开列明；未知规则和未经验证参数不能直接成为实盘配置。

## 〇 一页结论

**建议以分钟级的相对强弱动量和放量突破为首批研究对象，先建立统一的数据、成本、回放、执行与风控框架。** 2–10 分钟可作为重点观察区间，同时检验更长持有期。是否可交易，应由实际可成交价格下的样本外净收益决定，现有材料尚未证明任何策略已有盈利优势。

首版建议采用日本普通股票、长仓、日内平仓、不使用杠杆的研究配置。做空、双腿对冲、竞价和隔夜策略分别准入。本文中的研究优先级和初始风控数值是设计建议，不是已验证的最优参数。

### 决策漏斗

任何候选策略按以下顺序过滤，前一层不通过就不进入下一层：

```text
① 通道约束     交易及行情权限、数据粒度、限速、执行、借券  → 淘汰依赖不具备能力的策略
        ↓
② 时间尺度     信号收益曲线 + 数据质量 + 执行压力测试       → 首轮重点 2–30 分钟，无硬性最短周期
        ↓
③ 成本门槛     同一收益口径下的净优势为正且有不确定性余量 → 成本不重复扣除
        ↓
④ 股票适配     流动性、tick 占价比、波动、量能结构、借券      → 每日计算 Tradability
        ↓
⑤ 数据需求     策略所需数据是否在 L1 / 逐笔额度内可靠获得
        ↓
⑥ 样本外净收益 无前视回放 + 保守成交 + 压力测试
        ↓
⑦ 执行与风控   仿真、影子运行、小额实盘
```

### 核心立场

1. **研究定位是多股票扫描和受控执行**：在分钟尺度识别价格、量能和相对强弱异常。事件、多日和组合策略是后续候选；期货对冲必须先解决实时数据、权限和合约粒度，不能假定 API 已具备全部能力。
2. **我们要建的是“策略淘汰机器”，而不是策略清单**：所有信号走同一套数据、成本、延迟和成交模型，由数据决定持有期和去留。
3. **默认 NO_TRADE**：任何数据缺失、状态未知、成本无法估计的情形一律不开仓。

## 一 材料共识和证据边界

三份材料共同强调：先看券商通道和成本，再选择股票及策略；用相对强弱、成交量和价格结构识别异常；将午休、竞价、特别报价等日本市场机制纳入系统；用滚动样本外检验淘汰不稳定信号。

材料对优先级存在差异。《codex思路》更重视残差动量和 Lead-Lag，《策略汇总》更重视多因子趋势与 VWAP 回归，《claude思路》同时重视多日持仓、事件和配对。本文建议先研究数据要求较少、收益归因清楚的长仓策略，再加入同步、借券和多腿执行要求更高的方向。

### 原稿报告值的证据状态

以下数字只有原稿自述，当前目录没有原始行情、订单日志或计算程序，不能在本文中称为已复现实测：

| 材料报告值 | 可以表达的含义 | 需要补齐的证据 |
| --- | --- | --- |
| 30 只股票，有效盘口事件速率中位数约 0.264 次每秒 | 某种事件定义下的更新频率 | 股票池、采样期间、事件筛选及去重规则 |
| 更新间隔约 3.8 秒 | 上述事件率的倒数 | 不能据此推导行情延迟或数据陈旧程度 |
| 下单确认中位数 262 毫秒，p99 为 741 毫秒，199 个样本 | 材料所述券商确认耗时 | 计时起止点、订单类型、路由、日期和原始回报；尾部分位数样本有限 |
| 撤单再挂约 430 毫秒 | 两个耗时中位数相加的估算 | 完整撤单确认和重新下单流程的联合测量 |
| 中位价差 7.6 bps | 材料所述样本的价差统计 | 时段、股票、报价类型、权重及异常过滤 |

1 bps 等于 0.01%。材料中的 40–60 bps 入场门槛、50–150 bps 异常偏离、上涨 0.4%、止损 0.3%、止盈 0.6%、放量 1.8 或 2 倍、65% 主动买入比例，以及示例胜率和收益，均视为待检验候选或说明性例子。

## 二 IBKR 通道和账户条件

### 行情和接口

| 条件 | 当前官方口径 | 对策略的影响 |
| --- | --- | --- |
| 普通流式 L1 行情 | Watchlist 行情由时间快照生成；当前官方表列亚洲产品更新周期为 250 毫秒 | 不等于每 250 毫秒一定有变化，也不等于端到端延迟；不能视作完整逐笔事件流 |
| Tick-by-Tick | 同时订阅上限为总行情线路数的 5%；同一合约 15 秒内不能请求超过一次 | 100 条线路对应约 5 个逐笔订阅额度；先核实账户权限和流的配额占用 |
| API 请求频率 | 当前文档为每个客户端连接每秒请求上限等于最大行情线路数除以 2；100 条线路对应 50 次每秒 | 实际版本和设置仍须确认；持续回传行情不按每个更新重新计算请求，风险动作需要预留额度 |
| 历史行情 | 30 秒或更小 K 线有重复请求及密集请求限制 | 采集任务要排队、缓存和续传；这些规则不能直接套到所有分钟 K 线 |
| Level II 深度 | API 支持市场深度，但不保证展示每一个报价，且不含 odd-lot；订阅另有额度及权限要求 | 可作辅助特征；盘口重置后须清空重建，不能假设拥有完整队列信息 |
| OSE 期货 API 数据 | 当前官方列 OSE 实时行情和历史 K 线不可经 API 获取，仅有 15 分钟延迟流 | 不能把该延迟流用于分钟级基准、Lead-Lag 或自动对冲；需先解决可靠实时数据来源 |

行情口径见 [IBKR Market Data Update Frequency](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-live/top-of-book-l-1/market-data-update-frequency)、[Tick-by-Tick Introduction](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-live/tick-by-tick-data/introduction) 和 [API Pacing Limitations](https://www.interactivebrokers.com/docs/tws-api/doc/pacing-limitations/introduction)。这些是产品和接口规则，实际 TWS、Gateway、API 版本及配置须随实验保存。

L2 与 OSE 数据边界分别见 [IBKR Market Depth](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-live/market-depth-l-2/introduction) 和 [IBKR Live Data Limitations](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-live/live-data-limitations)。交易权限、TWS 可见行情和 API 可用实时行情分别验证，不能相互替代。

30 秒或更小历史 K 线应避免：15 秒内重复相同请求；2 秒内对同一合约、交易所、Tick Type 发起 6 次或更多请求；10 分钟内超过 60 次请求。BID_ASK 请求计两次。分钟级历史采集仍需要控制并发和应对节流，不能将规则范围之外理解为无限吞吐。见 [IBKR 小周期历史数据限制](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-historical/historical-data-limitations/pacing-violations-for-small-bars-30-secs-or-less)。

### 时间尺度适配分级

**交易周期应通过信号衰减和执行压力测试确定。** 以下分级是基于通道条件的先验判断，用于决定研究投入顺序，不是结论：

| 预测或持有周期 | 先验适配度 | 理由 |
| --- | --- | --- |
| 10–500 毫秒 | 暂缓 | 当前未证明数据完整性、端到端执行和队列优势 |
| 1–5 秒 | 暂缓 | 未证明该周期在实际数据和执行条件下仍有可成交净收益 |
| 5–30 秒 | 后续研究 | 逐笔需求取决于具体信号，先验证覆盖和延迟后的收益 |
| 30 秒–2 分钟 | 可研究 | 作为入场确认或独立信号；短持有期需对应粒度数据 |
| **2–10 分钟** | 首轮重点 | 相对较少依赖队列速度，可用分钟特征建立明确基线；仍需证明净优势 |
| 10–60 分钟 | 可研究 | 延迟相对影响可能降低；长持有期不保证能覆盖成本 |
| 数小时至数日 | ✅ 可研究 | 延迟不敏感；需另算隔夜跳空、事件和汇率 |

判断依据是**从当时可用数据形成信号，到实际可成交入场和退出的完整路径，在延迟压力下是否仍保留净优势**。不设置“持有期是 p99 之和的 50–100 倍”这类未经验证的门槛；不同耗时的高分位数相加也不代表联合路径的 p99。券商确认不是交易所接收或成交时间，无法观测的部分需明确标注，并使用保守情景。分钟级策略同样检查行情年龄、流健康和成交质量。

### 数据需求分层

策略能否在 IBKR 上落地，取决于它需要的最低数据层级：

| 数据层级 | 可获得性 | 可支持的信号 | 代表策略 |
| --- | --- | --- | --- |
| 1 分钟 K 线 + L1 快照 | 权限和线路额度足够时覆盖研究池 | 收益、残差、量能、近似或已验证 VWAP、突破、价差、简单加权盘口价 | 首版残差动量和放量突破 |
| Tick-by-Tick Last | 100 行情线路时约 5 个逐笔订阅额度 | 该流口径的成交计数和速度；主动方向还需匹配有效报价 | 成交流动量的增量研究 |
| Tick-by-Tick BidAsk | 与 Last 共享逐笔订阅额度，按请求流核算 | 价差、报价持续性、报价事件不平衡 | 辅助过滤和报价 OFI 研究 |
| Level II 深度 | 另有订阅额度、权限及覆盖限制 | 可观察深度变化，不假设知道真实订单或队列位置 | 仅作辅助特征 |

**首版只使用第一层。** 第二、三层用于“候选股票升级观察”（见下文额度调度），研究其对第一层信号的增量。

### Tick-by-Tick 额度调度设计

逐笔额度远少于股票池，因此采用“全池 L1 扫描 + 少数逐笔升级”的两级结构：

```text
全池（20–30 只）L1 + 1 分钟 K 线
        │  先过数据及成本条件，再按已冻结的信号与可交易性规则排序
        ▼
Top N（N ≤ 逐笔额度 − 预留）升级为 Tick-by-Tick Last
        │  升级后至少保持 M 分钟（避免 15 秒重复请求限制和频繁切换）
        ▼
持仓股票优先保留逐笔；平仓或信号消失后降级
```

规则：实际额度按订阅流计数，Last 和 BidAsk 不能按“一只股票一个额度”预算；同时核对 TWS 与 API 共享资源。仅为确实支持逐笔、且策略需要的基准代理预留额度。IBKR 当前仅对 CME 上的指数提供指数逐笔，不能为 TOPIX 或日经现货指数默认申请逐笔，见 [Tick-by-Tick 支持边界](https://www.interactivebrokers.com/docs/tws-api/doc/market-data-live/tick-by-tick-data/introduction)。

持仓和执行风控所需数据优先保留。切换先确认取消及容量释放，遵守同合约 15 秒请求限制；新流积累足够完整窗口之前，相关特征标记为未就绪。保存订阅起止、候选排序、未入选标的和缺失原因，保留一小部分预先指定的观察样本检验选择偏差。缺乏逐笔只关闭依赖逐笔的功能，不能把首版 L1 策略全部判为失效。

### 账户和交易能力

上线前必须确认账户所属法人、现金或保证金类型、日本股票权限、行情权限、费率方案、路由方式和 JPY 资金。全球 IBKR、IBSJ 现货股票、信用交易和 CFD 的规则不能混用。

IBSJ 现金账户禁止用同一笔资金，在同一结算日对同一股票进行受限的“买入、卖出、再买入”；如果账户另有足够独立资金，情况可能不同。因此系统需要记录可用资金及同股资金占用，不能把平仓后的销售款一律视为可再次使用的现金。见 [IBSJ Trading Rules](https://www.interactivebrokers.co.jp/en/trading/trading-rules.php)。

做空需要逐股检查交易权限、可借数量、指示借券费、价格限制及保证金。可借量和费用不是锁定承诺；多腿策略还要计入无法借券和被迫回补风险。IBSJ 当前不支持个人保证金账户少于 51 个交易单位订单的卖空价格限制豁免。见 [IBKR Short Securities Availability](https://brokerage.ibkr.com/en/trading/short-securities-availability.php) 和 [IBSJ Trading Rules](https://www.interactivebrokers.co.jp/en/trading/trading-rules.php)。

**市场风险对冲候选**：指数期货不需要股票借券，但无法替代某只股票的空头腿。OSE 产品还存在上述 API 实时数据限制；解决数据、合约、保证金和交易权限后，才进入第八章的独立对冲验证。

### 与 kabu Station 等本地券商的分工

若比较 kabu Station 等其他券商，分别测量行情完整性、执行与撤单延迟、成本、权限和异常恢复能力，再确定策略分工；仅凭“本地券商”身份不能认定存在排队优势。不同券商可以共用研究方法，但必须使用各自的数据、成本和成交模型。当前文档仍以 IBKR 分钟级策略为主。

## 三 按订单金额计算交易成本

### 佣金基础

核查时日本股票公开费率为 Fixed 单边成交额的 0.08%，最低每单 80 日元；Tiered 第一档单边 0.05%，最低每单 80 日元，另有适用第三方费用。是否适用于实际账户必须先确认。IBSJ 页面说明日本消费税已包含，其他实体按各自适用口径处理。见 [IBSJ 日本股票费率](https://www.interactivebrokers.co.jp/jp/pricing/commissions-stocks-asia-pacific.php?re=apac)。

单边佣金的基础表达式为：

```text
commission_jpy = max(order_notional_jpy × commission_rate, minimum_jpy)
commission_bps = commission_jpy / order_notional_jpy × 10000
```

**最低佣金与比例佣金的切换金额**：`minimum_jpy / commission_rate` 对 Fixed 为 **100,000 日元**，对 Tiered 第一档为 **160,000 日元**。这是费率函数的拐点，不是策略盈亏平衡点，也不是硬性订单下限。Tiered 在 160,000 日元以下也可能更便宜，例如 120,000 日元单边订单的基础佣金为 Fixed 96 日元、Tiered 80 日元，第三方费用再按路由计入。先按风险预算决定数量，再核算净优势；不能为了摊薄最低佣金扩大仓位。

以下为买卖名义金额近似相同、每边只有一张订单时的计算示例。Tiered 列尚未加入第三方费用：

| 单边订单金额 | Fixed 往返佣金 | Fixed 往返 bps | Tiered 第一档往返佣金 | Tiered 往返 bps |
| --- | ---: | ---: | ---: | ---: |
| 50,000 日元 | 160 日元 | 32 | 160 日元 | 32 |
| 100,000 日元 | 160 日元 | 16 | 160 日元 | 16 |
| 300,000 日元 | 480 日元 | 16 | 300 日元 | 10 |
| 1,000,000 日元 | 1,600 日元 | 16 | 1,000 日元 | 10 |

小额订单的最低佣金可能使策略失效，也可能使 Tiered 没有成本优势。官方还注明：直接路由的 API 订单不能使用 Tiered，SMART API 订单可用两种方案；部分成交后修改订单等情形可能重新计算最低佣金。路由及改单规则应进入成本模型，见 [IBSJ 日本股票费率说明](https://www.interactivebrokers.co.jp/jp/pricing/commissions-stocks-asia-pacific.php?re=apac)。

TSE 的第三方费用随市场板块和账户税口径变化。例如普通 Prime 股票，费表列交易所费用 0.002%、清算费用 0.0007%；IB-JP 对应含税数值为 0.0022% 和 0.00077%。原稿列出的每单 2.70 日元 Access Fee 不能直接加到所有普通单股订单，该条款有单股和篮子交易的例外。见 [IBKR TSE 费用表](https://www.interactivebrokers.com/en/accounts/fees/TSE-JP-StkFees.php?nhf=T)。SMART 路由是否会把日本股票订单送往 PTS 及其对费用、成交的影响，需按账户实测确认。

### 成本口径和开仓门槛

统一保留两套收益口径：

1. **信号收益**：从信号时刻的中间价计算价格变化，用来观察方向及不同持有期的响应；交易成本在之后估计。
2. **可执行净收益**：按模拟或真实的入场、出场成交价计算，扣除佣金和尚未包含的费用。已经按 ask 买入、bid 卖出，或使用真实成交价时，不能再次扣一遍价差及已体现的滑点。

如果引用材料报告的 7.6 bps 价差，在买卖两边各跨约半个价差、价差近似稳定的假设下，100,000 日元 Fixed 订单的基础往返成本约为 23.6 bps，50,000 日元订单约为 39.6 bps。两者均未包含进一步冲击和其他适用成本；这只是算例，不能代表当前股票池成本。

开仓条件应为：

```text
cost_bps(size) = 往返佣金及费用 bps + 从信号价到实际执行的预期价格损耗 bps

信号研究：E[mid_return_bps | 信号、股票、时段、规模] > cost_bps(size) + 不确定性余量
成交回测：E[fill_to_exit_gross_bps | 实际执行条件] - 尚未包含的费用 bps > 不确定性余量
```

所有项统一为往返 bps，金额费用按相同名义金额转换；每次费用扣除均标明已在哪一步体现。逆向选择通过成交条件下的收益及成交后价格表现评估，已体现于成交毛收益或执行损耗时不另扣。门槛随规模、流动性和执行模式变化，不统一写死为 40–60 bps。借券、融资、换汇和多腿失配费用在适用策略中另计；固定行情订阅和运维费用在月度净收益中核算。

### 换手与净收益的稳健性

净收益不只看总额，还要看它对成本估计误差有多敏感。两个说明性例子：

| 情形 | 单次净优势 | 每日次数 | 每日净收益（每笔 100,000 日元） | 实际成本比估计高 5 bps 后 |
| --- | ---: | ---: | ---: | ---: |
| A 高换手 | 12 bps | 50 | 6,000 日元 | 3,500 日元（−42%） |
| B 低换手 | 70 bps | 3 | 2,100 日元 | 1,950 日元（−7%） |

A 名义收益更高，但成本误差、滑点恶化或成交率下降都会迅速吞掉利润，同时更容易碰到 API 限速、行情额度和同股资金规则。评估时同时报告：

```text
gross_edge_to_cost_ratio = 同一口径的单次预期毛优势 bps / 往返成本 bps
cost_breakeven_shift = 在相同订单集合下使净收益归零所需的额外成本 bps
```

同时报告净优势的置信区间和实测执行损耗分布。压力情景及通过阈值在查看测试结果前冻结；不把“成本标准差数倍”作为通用硬门槛。降低订单金额会提高最低佣金的有效 bps，因此调整规模后必须重新通过成本准入。

## 四 股票池、诊断指标和所需数据

### 股票池规模和硬性条件

建议从 20–30 只高流动性普通股票开始研究，规模受实际行情额度和资金约束。这是初始采集建议，不代表已有该股票池。市场基准与行业基准也占用行情资源。扩大到数百只之前，应先证明数据覆盖、订阅调度和资金分配可控。

普通国内股票以 100 股为交易单位；ETF 等产品另行确认。呼值取决于证券类别和价格区间，不能为全池写死一个 tick。交易前从合约及市场规则取得合法价格和数量单位。见 [JPX Trading Unit](https://www.jpx.co.jp/english/equities/trading/domestic/03.html) 和 [JPX Tick Size](https://www.jpx.co.jp/english/equities/trading/domestic/07.html)。

**呼值的两个实务要点**：

1. 截至整理日期，细呼值表适用于 **TOPIX500 成分股，即 TOPIX100 与 TOPIX Mid400**；不能把 Mid400 当作其他普通股票。细呼值本身不证明净交易优势。
2. 呼值随价格档位变化，应在定价时按证券及当前价格查询。JPX 已公布 2027 年 3 月 1 日改为流动性分类，历史回放与将来交易均应按规则生效日选择版本，见 [JPX Tick Size](https://www.jpx.co.jp/english/equities/trading/domestic/07.html)。

先应用硬性条件：交易权限正确、实时行情有效、买卖报价合法、可用资金足够、至少一交易单位符合风险预算、没有不允许的市场状态。随后按流动性和策略表现排序。

### 单股诊断指标

建议以 60–120 个交易日启动诊断，按滚动窗口更新。分钟 K 线用于收益和量能；价差和报价频率用 L1，竞价成交占比用可靠竞价数据，借券和事件用独立来源。连续交易指标不混入午休和板寄せ；缺少数据的指标标记为缺失，不能从分钟 K 线硬推：

| 指标 | 计算方式 | 指向 |
| --- | --- | --- |
| 日均成交额 ADV | 近 60 日平均成交额，另报中位数及近 5 日变化 | 容量和近期流动性变化；低流动性可能也不适合事件策略 |
| tick 占价比 | 呼值 ÷ 价格 × 10000 | 与预期收益和成本比较；10 bps 只作诊断例子，不作通用淘汰线 |
| 平均价差 | 用 L1 按时段统计 tick 数和 bps | 1 tick 不代表被动挂单有利润；挂单质量需独立成交证据 |
| 日内波动 | 分钟收益标准差、日内 ATR ÷ 价格 | 波动必须远大于往返成本，否则日内无空间 |
| 收益自相关与 Variance Ratio | 5 分钟、30 分钟、日频分别计算 | 只作诊断：VR < 1 提示回归倾向，VR > 1 提示趋势倾向 |
| 竞价成交占比 | 开盘、收盘竞价成交量 ÷ 全天 | 占比高的股票可进入竞价模块研究 |
| 与市场、行业的关系 | beta、R²、残差波动、残差自相关 | 残差信号的可解释性与稳定性 |
| 借券可得性 | shortable 状态、可借量、指示费率 | 能否带空头腿 |
| 事件密度 | 决算日、指数入替候选、TOB、自社株买い | 事件驱动候选，或日内策略的事件过滤 |
| 1 交易单位金额 | 价格 × 100 | 仓位粒度；过高时小资金无法分散，过低时受最低佣金影响 |

VR、自相关、协整和半衰期在计算时需要控制买卖价跳动、日内季节性、重叠样本、午休断点和市场状态变化；它们**不直接决定**某股适合哪类策略，最终以交易规则的样本外净收益为准。

### Tradability Score

每天收盘后计算可交易性排序，用于次日股票池和逐笔资源分配。它评估执行条件，不替代信号预期收益，也不绕过硬性风险条件。首版只使用全池具有相同来源和口径的基础指标：

```text
base_score = Σ(weight_j × 同口径指标的训练期标准化得分_j)
基础指标：成交额、价差 bps、呼值 bps、报价有效率和覆盖率
扩展指标：可靠成交频率、实际执行损耗、与订单模式匹配的真实成交比例
```

首轮可用等权基础排序作为对照，权重在训练期冻结，随后只用验证或后续真实成交校准。缺项不能随机分摊权重后与完整得分混排；为不同数据覆盖版本分别报告。缺失成交计数时不使用该项；报价变化频率不是延迟指标。可成交限价和被动限价使用不同质量指标，纸面成交不能作为真实排队或成交概率证据。逐笔升级后的指标先检验增量，再决定是否纳入排序。

### 诊断特征到策略族的映射

| 策略族 | 需要的特征 | 在 IBKR 上的可行性 |
| --- | --- | --- |
| tick 级 scalping 或做市 | 逐笔数据、低延迟、排队优势 | ❌ 不在本系统做 |
| 日内残差动量 / 放量突破 | 高流动性、tick 占价比低、分钟级残差有持续性、量能季节性稳定 | ✅ 首版 |
| 日内均值回归 | 高流动性、分钟级回归倾向、ATR 充足、事件过滤可靠 | ✅ P2 |
| 竞价策略 | 收盘竞价占比高、指数成分股 | ⚠️ 先验证订单类型与数据 |
| 配对 / 统计套利 | 价差稳定、各腿可交易且费用明确、失配可处理 | P3；指数期货对冲不能替代个股配对的空头腿 |
| 多日 swing | 日频因子及隔夜风险可验证 | 可作低换手对照；另行准入 |
| 事件驱动 | TOB、指数入替、决算的时间和条款数据完整 | 可研究；公告瞬时反应可能很短，不能一概视为延迟不敏感 |

### 所需数据

| 数据或指标 | 用途 | 处理要求 |
| --- | --- | --- |
| 过去 60 日成交额、近期时段成交额 | 容量和冲击估计 | 历史股票池只能使用当时可获得的信息 |
| 买卖价、对应数量、价差 bps、呼值 bps | 入场成本与报价有效性 | 验证数量单位及价量同步，按时段统计 |
| 1 分钟成交价格和成交量 | 首版价格与放量信号 | 只使用已完成的 K 线，区分停牌和数据缺失 |
| 市场及行业基准 | 相对强弱和风险暴露 | 使用真实可获得的基准，记录 ETF 跟踪误差或期货基差 |
| 同时段历史成交量 | 相对成交量 RVOL | 对比历史相同钟点，控制开盘和尾盘的量能季节性 |
| 波动、MFE、MAE | 退出和风险预算 | 以明确可执行价格口径计算 |
| 成交回报和未成交记录 | 成交比例、滑点、超时 | 未成交信号也要保留，防止只看成功成交 |
| 公告时间、停牌、特别报价、价格限制 | 市场状态及事件过滤 | 保存当时已知信息，不用事后新闻决定是否交易 |

**基准选择**：首版优先验证可经 API 获得实时数据的日本指数 ETF 或足够广的股票篮子。OSE 期货延迟流不满足分钟级基准要求。行业 ETF 或同行篮子应检查报价年龄、覆盖和成分集中；篮子权重只用当时已知信息，原则上排除目标股并处理停牌及缺失。行业样本不足时退回市场单因子模型，不强行构造不稳定行业因子。

首版不使用缺乏可靠来源的成交笔数、主动买卖比例或大单指标。报价回调次数不是实际成交笔数；累计成交量跳变也不能还原每一笔交易。VWAP 优先用可验证的成交金额除以成交量；若由分钟 K 线近似，则单独标注近似口径，并验证与实时口径的一致性。

### 优先级总表

### 推荐的首批研究顺序

1. **简单放量突破基线**：先以相同股票池和执行框架验证评估器；ORB 作为独立版本。
2. **残差动量主策略**：重点观察 2–10 分钟并检验更长周期；与基线比较市场、行业调整的增量。
3. **极端偏离回归（5–30 分钟）**：只抓经波动标准化后的显著偏离，不抓普通小幅偏离。
4. **Lead-Lag**：只有领先资产及个股均有可靠实时数据、时间同步和可执行收益证据才推进；OSE 延迟流不满足条件。

## 六 首版长仓相对强弱放量动量

### 策略定位

策略族为日内方向交易，信号族为价格动量、量能和统计残差，执行采用有价格保护的可成交限价单。长仓残差信号仍承担市场及行业风险，不构成市场中性组合。IBKR 适配性属于待回放和成交验证的研究判断。

首版保留少量特征，避免把 EMA、VWAP、趋势、突破和动量这些相关指标计成多个独立证据。订单状态机和风控达到准入条件后，才能连接真实交易。

### 信号定义

在已完成的 1 分钟 K 线后进行评估。以 5 分钟为首个特征回看窗口，同时保存 2、10 分钟结果用于研究；测试前固定采用哪一组。

```text
stock_return_h = 个股过去 h 分钟收益
market_return_h = 市场基准同期收益
sector_excess_h = 行业基准同期收益 - gamma × 市场基准同期收益

residual_h = stock_return_h - alpha_h
             - beta_market × market_return_h
             - beta_sector × sector_excess_h

RVOL_h = 当前已完成 h 分钟成交量
         / 过去 20 个有效交易日相同时段成交量的中位数
```

alpha、beta 和 gamma 用信号之前的数据估计。行业因子先剔除市场共同成分，减少重复解释；行业缺乏可靠基准时先只用市场因子，并单独标注模型版本。基准含有目标股票时，应评估自包含影响。收益和回归截距必须对应相同时间尺度。

首版 VWAP 约定为当日累计成交额除以累计成交量，正常开盘成交纳入该口径；午休不补成交，下午不重置全日 VWAP。短窗收益、RVOL 和连续撮合诊断不跨午休，也不把竞价事件当作连续撮合事件。若数据源只能提供分钟近似 VWAP 或另一种成交覆盖范围，采用独立版本，在训练、回放与实时中保持一致，不能临时切换基准。

初始长仓候选同时满足：

1. 残差收益为正，超过训练期预先选择的阈值；例如从条件分位数中选择，而非抄固定 bps。
2. 同时段 RVOL 超过训练期确定的门槛；基准量过低、缺失或样本不足时不产生信号。
3. 价格位于当日累计 VWAP 上方，当前为正常连续交易，市场基准波动与价差没有触发预先冻结的异常阈值。

市场环境判断只使用当时可获得的基准 K 线、报价及状态信息，异常指标及阈值在训练和验证阶段确定。无法确认市场状态时标记为未知并阻断开仓，不能默认属于正常连续交易。

这些条件只生成候选信号。决策层还需要确认可执行净优势、持仓、活动订单、资金及所有风控条件。无法可靠估计某信号桶的条件收益时，继续记录观察，默认不交易。

### 待检验的增量特征

以下特征不进入首版规则，但在信号事件研究中一并记录，用于第二轮比较：

| 特征 | 定义草案 | 假设 |
| --- | --- | --- |
| 加速度 | `ret_short / h_short − ret_long / h_long`，例如 1 分钟与 5 分钟的单位时间收益差 | 上涨在加速的信号优于上涨已放缓的信号 |
| 残差持续性 | 过去 k 根 K 线中残差为正的比例 | 连续性强的残差更可能延续 |
| 市场方向 | 市场基准 h 分钟收益的符号与幅度 | 市场同向时长仓残差信号更稳 |
| 价差状态 | 当前价差 bps 相对该股同时段中位数 | 价差扩大时执行成本和逆向选择上升 |
| 成交流（逐笔可用时） | 按报价分类的主动买入量占比 | 对 RVOL 提供方向信息 |

### 入场与持仓

采用最新有效 ask 及预设最大入场价格生成买入限价；价格按当前合法呼值处理。信号在等待成交期间失效、成本超限或市场状态改变时撤单。有效期限由训练和回放确定，不能无限追价。

同一股票只允许一份开仓意图和受控的活动订单。首版不加仓、不摊低成本，不在平仓完成前反向开仓。部分成交后，成交数量立即计入持仓及风险；是否继续补齐剩余数量需要重新决策。

### 退出

首版以固定持有期作为可比较基线，研究 2、5、10、20 分钟退出；选择持有期只能使用训练和验证数据。持有期从首次成交开始，后续部分成交不重置计时。到退出时使用可执行卖价模拟或执行，不能默认以中间价成交。

风险止损、账户损失锁定、异常状态和时段结束优先于固定持有期。止损距离根据波动、价差和账户风险预算确定；信号减弱或 VWAP 跌破可作为后续独立退出版本，先与固定退出基线比较，避免一次引入过多自由度。

首版不跨午休、不隔夜。可成交限价单仍可能不成交，价格限制、停牌和连接异常也可能阻碍止损。因此“提交风险平仓”与“已经平仓”必须分开记录，并设置未能退出时的升级处理。

### 放量突破对照策略

先测试“突破前 20 根分钟 K 线高点、同时段 RVOL 达标、成本及风控通过”。在第 t 根 K 线完成后，突破水平取第 t−20 至 t−1 根的最高价，再判断第 t 根收盘价；信号 K 线不参与计算突破水平。使用相同股票池、成本模型和执行框架，以判断残差调整究竟带来多少增量。

开盘区间版本单独定义为 9:00–9:15 的有效连续交易区间，区间完成后才判断突破。实际开盘延迟、区间有效交易不足或特别报价时，该股票当天不开启此版本；不能用尚未结束区间的最终高低点提前下单。

## 七 P2 策略规则草案

以下规则只是进入研究的起点，与首版共用框架；P1 完成后每项独立测试。特征阈值可由训练期分位数选择；时段、权限和风险预算属于独立约束，不能由收益优化放宽。

### 极端偏离回归

```text
z_resid = (residual_h - mu_resid_h) / sigma_resid_h
vwap_deviation = (price - day_VWAP) / day_VWAP
z_vwap = (vwap_deviation - mu_vwap_deviation) / sigma_vwap_deviation

候选（长仓）：
  z_resid 或 z_vwap ≤ 训练期下尾分位数
  AND 最近 k 根 K 线的下跌幅度在收窄（价格下跌减速代理）
  AND 出现回归确认（例如收盘价重新高于前一根 K 线高点）
  AND 截至决策时无已知重大公告，当前趋势诊断允许回归，且非特别报价
```

历史中心 mu 和波动 sigma 使用信号之前、同股同时段且同尺度的数据，采用与当前相同的模型和 VWAP 版本。波动过小、缺失或样本不足时不计算有效 z 值。分钟价格下跌减速并不证明主动卖出量减少；如需真实卖压特征，另行验证成交分类。

财报、TOB、增发、重大公告和持续趋势中的下跌可能是信息重定价。消息状态未知或异常未能解释时不直接接盘。动量和回归策略在同股同时发出相反意图时，首版默认不新开仓。回归策略应按决策时可知的市场环境分组；事后“趋势日”标签只用于诊断，不得用于历史开仓筛选。

### 趋势回踩延续

```text
前提：过去 N 分钟残差动量信号成立（同首版）
回踩：价格回落至已冻结口径的当日 VWAP 或短期均线附近，回撤幅度不超过前段涨幅的设定比例
确认：回踩期间成交量低于上涨段，随后重新放量并收复前一根 K 线高点
```

与首版相比，它试图用更好的入场价换取更低的成交概率。必须报告“信号后从未回踩”的错失比例，不能只统计回踩后的交易。

### 横截面动量

每分钟在全池中按残差动量（结合 RVOL）排序，只对排名前 K 且通过成本与风控的股票开仓。其价值在于自动把资金和逐笔额度分配给最强信号，而不是对每只股票独立设阈值。需注意：同一时刻排名靠前的股票往往同属一个行业，组合层的行业集中限制必须生效。

### 多因子合成

《策略汇总》的“5 项满足 4 项即买入”属于等权计数，会把高度相关的 EMA、VWAP、突破、动量重复计分。本文的做法是：

1. 先逐个验证单因子在控制其他因子后的增量（例如在残差动量已知的条件下，VWAP 位置是否仍有信息）。
2. 只保留有增量的因子，用简单线性或分位数模型合成条件预期收益，样本外检验后再替代规则版本。
3. 合成模型输出的是预期收益估计，仍需经过成本门槛和风控，不直接产生订单。

## 八 事件、对冲和多腿策略的独立准入条件

**Lead-Lag**：用接收时间对齐真实可用信息，并在回放中加入各数据源的延迟。控制共同市场因子后，领先资产仍能预测落后资产的可执行收益，才能进入交易测试。较慢报价造成的表面领先关系不能直接解释为经济优势。候选领先资产包括日经 225 / TOPIX 期货、行业龙头、ADR 及美股同业（适用于开盘时段），以及汇率。

**配对统计套利**：收益 beta 残差与价格层面的协整不是同一个对象。需要检验价差模型的滚动稳定性、回归速度、两腿成本及借券，并模拟一腿成交另一腿失败的处理。只有单边成交时，系统必须承认存在裸露风险。

**竞价策略**：IBSJ 官方列出 TSE 股票的 MOC 和 LOC 支持，并说明上午竞价订单不会自动延续到下午；实际 API 合约、截止时间和订单行为仍需验证。开收盘成交并无保证。具备订单类型不代表已取得竞价失衡数据。见 [IBSJ TSE 竞价订单规则](https://www.interactivebrokers.co.jp/en/trading/trading-rules.php)。

### 事件驱动

事件策略可以覆盖公告后的多日反应，也可能依赖很短的瞬时窗口。首轮只研究能跨越实际执行延迟的事件后响应；每类事件需要准确发布时间、条款和可交易价格，不能笼统认定为延迟不敏感。

| 事件 | 研究对象 | 关键数据 | 主要风险 |
| --- | --- | --- | --- |
| TOB / MBO | 公告后市价与收购价的价差 | 收购价、期限、成立条件、下限、竞争方 | 撤回、条件不成立、价差长期不收敛 |
| 指数定期入替（日经 225、TOPIX 规则变更） | 公告到生效日之间的需求冲击 | 公告日、生效日、预测候选、被动资金规模 | 预期已提前定价、生效日收盘竞价冲击 |
| 决算（PEAD） | 决算惊喜后多日漂移 | 精确发布时间、市场预期或简单惊喜代理 | 发布时间在盘中或盘后不同，需分开；跳空 |
| 自社株买い / 股东回报 | 公告后的价格反应与执行期 | 回购上限、期间、执行进度 | 信号已被开盘价完全反映 |
| 增资、大股东减持 | 公告后的价格压力与恢复 | 发行价、定价日、规模 | 信息重定价，与回归策略冲突 |

规则：事件数据只用发布当时可获得的版本；发布时间精确到分钟并标注时区；日内策略在事件股上默认禁止开仓，事件模块单独准入。

### 期货对冲与跨市场组合

长仓残差策略承担市场风险。期货对冲作为独立后续模块，在实时数据、历史数据、交易权限和风险预算均通过后研究；当前 OSE API 延迟数据不满足分钟级自动对冲准入。

合约粒度先以名义金额衡量，名义金额不等于保证金。以下指数点位仅为算例：

| OSE 合约 | 合约乘数 | 算例期货点位 | 一张合约名义金额 |
| --- | ---: | ---: | ---: |
| 日经 225 mini | 每点 100 日元 | 40,000 | 4,000,000 日元 |
| 日经 225 micro | 每点 10 日元 | 40,000 | 400,000 日元 |
| mini-TOPIX | 每点 1,000 日元 | 3,000 | 3,000,000 日元 |

乘数见 JPX 的 [日经 mini](https://www.jpx.co.jp/english/derivatives/products/domestic/225mini/01.html)、[日经 micro](https://www.jpx.co.jp/english/derivatives/products/domestic/225micro-futures/01.html) 和 [mini-TOPIX](https://www.jpx.co.jp/english/derivatives/products/domestic/mini-topix-futures/01.html) 合约规格。实际开放合约、价格、保证金和交易时段另行取得，不能用算例点位下单。

对选定期货估计同期收益 beta，长仓组合的目标对冲方向为卖出：

```text
beta_exposure_jpy = Σ(position_value_i_jpy × beta_to_selected_future_i)
target_futures_quantity = - beta_exposure_jpy / (futures_price × multiplier_jpy)

actual_quantity = 在合法整数合约、保证金和风险约束下选择的数量
residual_beta_exposure = beta_exposure_jpy + actual_quantity × futures_price × multiplier_jpy
```

beta 只能使用过去数据，必须对应所选期货及收益尺度；不能直接搬用对市场 ETF 的 beta。比较不对冲、向下和向上取整的残余风险及费用，不自动四舍五入，也不强行开一张造成过度对冲。实时监控毛敞口、净 beta、保证金、基差、换月和两腿失配；单腿失败时重新处理真实风险。组合报告分开展示现货损益、对冲损益、费用及残余 beta，不能把估计残差当成实际组合利润。

跨市场信息按实际日历和时区分类。美股前一常规交易时段信息可作为日股开盘候选；港股连续交易与日股存在部分重叠，可以研究同步传导，不能统一归为隔夜。港股时段见 [HKEX Securities Market Trading Hours](https://www.hkex.com.hk/Services/Trading-hours-and-Severe-Weather-Arrangements/Trading-Hours/Securities-Market)。各市场均需实时数据、汇率、权限及成本验证。

## 九 日本交易时段和数据处理

普通 TSE 股票上午交易时段为 9:00–11:30，下午为 12:30–15:30。下午连续撮合在 15:25 结束，15:25–15:30 为收盘前订单接受阶段，其间不撮合，15:30 进行板寄せ。该安排自 2024 年 11 月 5 日实施。见 [JPX Trading Hours](https://www.jpx.co.jp/english/equities/trading/domestic/01.html)、[JPX Transaction Methods](https://www.jpx.co.jp/english/equities/trading/domestic/04.html) 和 [JPX 2024 年市场变更](https://www.jpx.co.jp/english/corporate/news/news-releases/1030/20241105-01.html)。

以下为首版日内策略的建议操作安排，全部使用 Asia/Tokyo。策略窗口不是交易所官方时段：

| 时间或状态 | 首版处理 |
| --- | --- |
| 开盘前 | 核对日历、资金、合约、权限、持仓和活动订单 |
| 9:00 开盘及早段 | 建立当日量能和 VWAP；开盘区间策略收集完整区间 |
| 9:15 之后 | 在有效连续交易状态中允许通过准入的候选策略 |
| 上午结束前 | 建议最晚计划退出时间为 11:25；之后核对持仓和活动订单 |
| 11:30–12:30 | 禁止连续撮合策略开仓，午休不补成零收益分钟 |
| 12:30 午后开盘 | 午休跳空单独处理；重新确认报价和状态，短窗信号重新积累 |
| 下午结束前 | 建议最晚计划退出时间为 15:15；15:20 再核对持仓和活动订单 |
| 15:25–15:30 | 首版保持无持仓且无活动订单；竞价模块另行准入 |
| 收盘后 | 对账、保存日志、核算成本和更新研究报告 |

每次开仓必须满足：距离配置中的最晚计划退出时间，大于订单等待期限、计划持有期与退出缓冲之和。时段退出优先于固定持有期；发生提前退出时，按时段退出单独统计。异常情况下未能平仓时，进入风险处理，不能假装已完成日内清仓。

历史样本按交易制度分段；跨午休、隔夜和竞价的收益独立标注，不混入普通连续交易标签。特别报价、停牌和价格限制应保留状态记录。正常状态研究可以排除这些区间，但必须另做异常退出压力测试，不能只留下容易成交的交易日。拆股等企业行动的研究复权与实际下单价格分开存储。

**数据处理补充**：

- 计算收益自相关、VR 和滚动特征时，午休按“短隔夜”处理，不跨午休拼接窗口，否则会产生虚假的均值回归。
- 2024 年 11 月 5 日前后的尾盘分钟结构不同，涉及尾盘的特征和标签按制度分段估计。
- 市场状态切换明显的时期（例如 2024 年 8 月初的大幅波动）单独标注，用于检验策略在极端环境下的表现，而不是从样本中剔除。

## 十 系统架构和订单生命周期

系统按五层划分，风控拥有最高优先级：

| 层 | 职责 | 首版必要能力 |
| --- | --- | --- |
| 信号层 | 计算候选优势 | 特征、窗口、归一化、数据有效性、信号到期 |
| 决策层 | 结合状态产生交易意图 | 默认 NO_TRADE，区分开仓、持有、减仓和退出 |
| 执行层 | 将意图变成安全订单 | 限价保护、撤改单、部分成交、拒单、超时和去重 |
| 风控层 | 硬性阻断及风险退出 | 仓位、资金、损失、数据和连接异常、时段、停机锁定 |
| 组合层 | 控制多股票整体风险 | 总敞口、行业集中、相关持仓和资源分配 |

策略不能直接越过决策及风控调用券商下单。最低订单状态需要区分：待提交、待确认、活动、部分成交、撤单中、已成交、已撤、拒绝、失效和状态未知；持仓状态独立维护。订单同时保留策略归属及客户端标识；共享账户中的人工或其他策略持仓计入账户风险，自动撤平只作用于明确受本系统管理的订单和持仓。

关键行为如下：

- 撤单请求发出后，不把订单标记为已撤。若此时发生迟到成交，按真实成交更新持仓，重新核算剩余数量。
- 撤单或提交结果不明时先查询券商订单、执行和持仓，不盲目重复下单。安全的修改规则由适配器明确实现。
- 重复、乱序回调不得重复累计成交或生成新的订单意图。记录 orderId、permId、execId 和策略意图标识。
- 断线后禁止新开仓；重连完成账户、活动订单和成交核对，才进入可交易状态。
- 保护性订单只能在确实支持且验证了父子关系、数量和撤单联动时使用，不把本地止损判断当作服务器保护。
- API 调度限速并给撤单、风险退出预留容量；行情处理不能被文件写入或网络查询阻塞。

KILL_SWITCH 是“停止新交易、尝试取消活动订单、在可交易条件下处理剩余风险并锁定”的流程。断线或停牌时无法保证立即全撤全平，必须保留未解决状态并提示人工处理。后续强信号不得解除锁定。

## 十一 统一策略评估器

评估流程为“原始数据、特征、候选信号、可执行订单模拟、成交与退出、费用、净收益及分组报告”。信号事件研究和完整成交回测分开，防止把方向预测收益当成策略收益。

```text
Raw Market Tape → Feature Engine → Candidate Signal
      → Forward Returns（多持有期，信号收益口径）
      → Executable Simulation（延迟、限价、成交概率）
      → Cost Model（按金额的佣金、费用）
      → Net Return → 分组、稳定性、压力测试 → 适配结论
```

每个信号保存以下信息：

| 类型 | 最低记录字段 |
| --- | --- |
| 研究标识 | 股票、交易日、策略版本、参数、数据源、股票池版本 |
| 时间 | 源时间戳及其含义、接收时间、特征完成、决策、提交、券商确认、成交、撤单请求和确认 |
| 市场上下文 | bid、ask、对应数量、价差、呼值、量能、基准、市场状态、行情类型 |
| 信号与决策 | 特征值、预期收益及其估计依据、成本估计、意图和风控拒绝原因 |
| 执行 | 买卖方向、策略归属、clientId、orderId、permId、execId、signal_price、limit_price、目标数量、fill_price、fill_qty、cum_fill_qty、remaining_qty、fill_delay、部分成交、拒单、超时、撤单请求及确认时间、剩余持仓 |
| 结果 | 毛收益、费用、净收益、MFE、MAE、持有期、退出原因、post_fill_return（成交后收益） |

L1 源若没有交易所时间戳，就不能据此计算交易所到本机的精确延迟。最后一次价格变化的时间不等于流的健康状态；行情有效性需要结合流连接、可获得的源时间和接收记录判断。

研究持有期可包括 5、10、30、60、120、300、600、1200、1800 秒；分钟 K 线无法可靠评估秒级成交路径，短周期必须使用对应粒度数据。只有成交 K 线而没有历史买卖报价时，可以筛选信号并做保守成本估计，不能声称已精确还原 bid/ask 成交。单根 K 线同时触及多个退出条件时，先后顺序未知，应使用保守假设或更细数据重放。跨休市标签单独归类。实际入场从决策后、考虑执行延迟且可获得的报价开始，不能使用决策当时已经过去的成交机会。

必须分别报告：信号数量、提交订单数、成交订单数、完成往返数、成交比例、每次成交收益和每次交易意图的实现收益。限价触价不等于成交；Maker 需要单独的保守成交模型或真实日志。被动限价单要特别检查**条件成交偏差**：成交的往往是随后价格不利的那部分订单，因此 post_fill_return 应与未成交信号的远期收益对比。

最终报告至少包括：不同持有期的毛收益和净收益、胜率、收益分布、MFE、MAE、日收益、回撤、尾部损失、换手、容量及成本敏感性，并按股票、时段和市场环境分组。

曲线在 5 分钟达到收益峰值，只说明候选退出时间，不等于 alpha 半衰期。半衰期必须有明确衰减定义和合理模型；价格价差的均值回归半衰期也不能直接替代方向信号的可执行持有期。

### 持有期曲线的判读

让数据决定周期，而不是先验规定“这是 1 分钟策略”。同一信号的远期收益曲线有两种典型形态：

```text
形态 A（峰值较晚的候选）     形态 B（衰减较快的候选）
5s   −3 bps                  100ms  +10 bps
30s  +5                      500ms  +15
1m   +18                     1s     +18
2m   +41                     5s     +3
5m   +67  ← 峰值             30s     0
10m  +55
30m  +12
```

上述数字均为示意。仅凭 B 在 1 秒仍有 18 bps、5 秒变为 3 bps，不能断言订单到达前优势一定消失；A 的收益峰值较晚也不保证能赚取该收益。用实际可获得的信息和入场路径检验成交后的剩余优势、净收益曲线及置信区间，才决定去留。

逐笔调度也属于回放的一部分：重现当时排名、升级时间、暖机、请求额度、缺失和降级。不能用历史全覆盖逐笔，给实时尚未升级的股票生成不可获得特征。

每个策略版本自动生成如下摘要（数值为占位符）：

```text

Horizon fixed in validation: ___ sec

All-intent PnL:     含未成交与部分成交的每次意图实现收益 ___ 日元
```

## 十二 回测和上线准入

### 时间切分与统计检验

建议先采集 60–120 个交易日用于启动研究，是否足够取决于交易数量、市场环境覆盖和置信区间。按时间顺序划分训练、验证和测试，并保留最终未参与选参的样本。滚动评估时只用过去估计模型；测试结果不能再被用于挑选最优参数后仍称为样本外。

剔除标签或持仓结果跨越训练与评价边界的样本，并按最长持有期、数据重叠和切分方式设置隔离区间。测试开始时可以使用此前已知的历史特征进行暖机，不能利用测试未来数据拟合 beta、阈值或标准化参数；不把“删除所有回看窗口”当作唯一的无前视保证。对重叠信号、同日多股的相关性，以交易日或相关样本块估计不确定性。记录测试过的策略及参数数量，并对多重筛选作调整。

首版收益验证必须满足：

1. 按真实订单规模、最低佣金和保守成交假设，样本外净收益有支持证据；只报告正均值而忽略区间和尾部风险不够。
2. 收益不依赖单一股票或少数特殊交易日，邻近参数有合理稳定性。
3. 加入更差延迟、价差、滑点、未成交、部分成交和退出困难后，仍符合预先设定的净收益及风险要求。
4. 动量策略与简单突破基线相比有可解释的增量；无优势的复杂特征删除。

### 阶段门槛

| 阶段 | 必须交付的证据 | 未通过时 |
| --- | --- | --- |
| 数据准入 | 合约、时段、实时权限、完整性、字段单位、成本版本明确 | 修复数据或减少策略所需特征 |
| 回放准入 | 无前视、成本无重复扣除、持仓和订单生命周期可重放 | 修复模拟及规则 |
| 样本外准入 | 净收益、不确定性、稳定性、压力测试及容量报告 | 淘汰、降频或继续观察 |
| 仿真和影子运行 | 重连、对账、止损、撤单和时段处理通过 | 修复系统；仿真成交不能证明真实队列优势 |
| 小额实盘准入 | 实际费用、成交比例、延迟、拒单、滑点与风险退出符合预算 | 停止扩容，回到原因分析 |

IBKR Paper 使用买卖一档模拟成交，不支持真实深度执行；止损、复杂订单和部分成交行为可能与实盘不同。Paper 验证连接及订单风控流程，影子运行验证当时信息下的实时意图，真实排队和滑点仍需小额成交证据。见 [IBKR Paper Trading 限制](https://www.ibkrguides.com/clientportal/aboutpapertradingaccounts.htm)。

任何阶段都允许 NO_TRADE。策略不足以覆盖成本时，应淘汰或延长周期，而非通过无限加杠杆或提高交易频率弥补。

### 小额实盘的持续监控与降级

进入小额实盘后，每日比较实盘与同期回放（用同一天 tape 重放）的差异：

| 监控项 | 含义 | 降级触发（初始建议，需冻结） |
| --- | --- | --- |
| 执行价格损耗 | 按买卖方向计算决策价到成交价的损耗，另报费用 | 滚动分布显著差于回放假设 |
| 成交率偏差 | 实盘成交率 − 回放成交率 | 持续低于回放 |
| 净收益偏差 | 实盘净收益 − 同日回放净收益 | 滚动窗口内超出预设置信带 |
| 延迟分位数 | 提交到确认的 p50 / p99 | p99 超出压力测试假设 |
| 安全异常 | 状态未知、持仓或活动订单不一致、断线及损失锁定 | 立即停止新开仓并进入查询、对账和风险处理 |

一般表现偏差按预设规则停止扩容、调整规模或频率、返回影子运行；每次调整规模重新核算最低佣金和净优势。安全异常不走渐进降级：立即阻断新开仓、核实券商状态、处理受控订单和持仓，并保持锁定；原因未解决及状态未核对完成前不恢复交易。一般拒单先分类；原因未知或影响持仓判断时按安全异常处理。

### 必须覆盖的异常测试

- 部分成交后发出撤单，撤单确认前继续成交，最终持仓和剩余量正确。
- 提交或撤单超时、重复和乱序回报，不重复开仓、不误判已平仓。
- 断线重连，本地与券商持仓或活动订单不一致时保持交易阻断。
- 日损失锁定和 KILL_SWITCH 触发后，任何信号都不能新开仓。
- 午休、下午重新开盘、15:25 时段切换、节假日和特别报价不沿用普通连续撮合逻辑。
- 小金额、部分成交改单和双腿订单的最低佣金计算正确；买卖价回测不重复扣价差。
- 价格限制、停牌或限价退出未成交时，真实记录剩余风险并进入升级处理。
- IBSJ 现金账户反复交易同股时，资金状态不会错误放行受限订单。
- API 请求接近限速时，撤单和风险退出仍能优先发出；逐笔订阅切换不违反 15 秒重复请求限制。

## 十三 初始风险配置建议

下表仅为首轮小额测试的保守配置示例，实际资本未提供，需在测试前按账户能力冻结。配置不得被策略自行放宽。市场跳空或交易中断可能造成实际损失超出预算。

| 项目 | 示例初始约束 |
| --- | --- |
| 交易方向和杠杆 | 长仓，无融资杠杆 |
| 单笔计划风险 | 账户净值的 0.1%，包含止损幅度、入场及退出费用和缓冲 |
| 订单金额 | 先服从风险、资金、合法数量和容量；按实际规模的成本判断可交易性，无通用 100,000 日元下限 |
| 单股名义持仓 | 不超过账户净值的 10% |
| 总长仓名义敞口 | 不超过账户净值的 50% |
| 同时持仓 | 不超过 5 只，并另设行业和高相关组合限制 |
| 日损失锁定 | 已实现加未实现净损失达到日初净值的 0.5% 时，停止开仓并处理持仓 |
| 首版同股开仓次数 | 每日最多一次，账户资金规则仍需独立核验 |
| 隔夜和午休持仓 | 首版不允许 |
| 订单与撤改单次数 | 按账户、API 及成交质量设置上限，避免无效密集请求 |
| 流动性容量 | 设置单日及短时段累计参与率上限，以回放和成交日志校准 |

账户净值、资金和风险预算先统一转换为 JPY，并保存换算时点。候选仓位按多个上限取最小值，然后向下取整为合法交易单位：

```text
candidate_quantity = 向下取整至合法交易单位的 min(
    单笔风险预算 / 每股止损与双边成本的初步估计,
    单股名义金额上限 / 入场价格,
    可用资金支持数量,
    流动性允许数量
)
```

最低佣金使总成本随数量变化，并非固定每股费用。候选数量 Q 取整后，必须按具体订单金额重新计算 `Q × 每股止损损失 + 入场费用(Q) + 退出费用(Q) + 缓冲`，确认不超过单笔风险预算；不满足时逐个交易单位缩减 Q，并重新核算所有上限。已经包含在止损损失或成交价中的滑点不重复计入。

风险预算分母必须使用日元每股的同一单位。挂单和部分成交也占用资金、仓位及风险额度。计算结果不足一个交易单位时跳过，不能为凑一手放宽风险限制。未实现损失按可执行退出价格估计，并避免多个策略重复计算可用资金。

**资金、风险与成本的相容性**：例如账户净值 100 万日元、单笔预算 0.1% 时，风险预算为 1,000 日元；100,000 日元订单若止损损失为 0.5%，约为 500 日元，再计入示例 Fixed 往返佣金 160 日元及其他成本，才判断能否通过。这只是预算算例，不是建议止损参数。若合法最小仓位超预算，或规模降低后无法覆盖成本，跳过或推迟实盘；不为跨过佣金拐点加仓，不为凑仓位缩窄合理止损，也不自动提高风险上限。

## 十四 建设顺序、路线图和当前判断

### 分阶段路线图

每一步以可验收结果结束，未通过不进入下一步：

| 阶段 | 内容 | 验收产出 |
| --- | --- | --- |

### 当前判断

当前缺少账户配置、原始实测日志、策略代码、回放结果和运行记录。五层 Gate 状态如下，N/A 表示证据不足以评分，不表示该层不需要实现：

| 层 | 当前评分 | 准入判断 |
| --- | --- | --- |
| 信号层 | N/A | 有候选逻辑，预测及净收益未经验证 |
| 决策层 | N/A | 未提供状态及规则实现 |
| 执行层 | N/A | 未提供订单、撤改单和回报处理证据 |
| 风控层 | N/A | 未提供硬性阻断及风险退出验证 |
| 组合层 | N/A | 多股票敞口与资源分配未经验证 |

**红线扫描未能判定通过。** 缺少证据不能等同于已存在缺陷，但也不能证明已具备 kill switch、部分成交处理、重连对账和日终退出。当前结论为：可进入数据采集与回放研究，尚无实盘准入证据；不作数值总评分或盈利承诺。

优先补齐的三项是：可靠数据与成本证据、完整订单生命周期及对账、优先级最高的账户风控与退出处理。策略方向上优先分钟级相对强弱和放量突破，回归、Lead-Lag、配对和竞价在各自条件成立后推进。

## 十五 原稿中需统一的概念

| 原稿中的简化说法 | 本文统一口径 |
| --- | --- |
| L1 回调频率决定行情陈旧时间 | 更新率、数据年龄、流健康和传播延迟分别测量 |
| 券商确认耗时就是订单到达延迟 | 提交、券商确认、交易所接收和成交是不同事件 |
| 两段耗时中位数相加就是撤单再挂下限 | 仅为估算，联合流程需要单独实测 |
| Microprice 必须有逐笔或 L2 | 简单加权盘口价可由同步 L1 价量计算；预测优势另验证 |
| 主动买卖比例就是 OFI | 成交方向不平衡与报价事件 OFI 分开；无法分类的成交保留为未知 |
| VR 小于 1 就能做回归 | 只是诊断，具体交易收益仍需成本和样本外验证 |
| beta 残差就是协整价差 | 收益回归和价格协整属于不同模型 |
| 收益峰值时间就是半衰期 | 峰值、信号衰减和价差回归半衰期分开定义 |
| 挂单成交就省下全部价差 | 成交概率、条件成交偏差、逆向选择和退出成本共同决定结果 |
| 多个指标达到四项就可以开仓 | 先验证增量信息，再经过成本、决策及风险准入 |
| 成交量大就是好股票 | 以 Tradability（更新频率、成交频率、价差、tick 占价比、滑点）综合排序 |
| 交易次数越多收益越高 | 看单次净优势、成本误差敏感度和容量，高换手放大成本估计误差 |
| 做空 = 对冲 | 个股做空依赖借券；市场风险对冲可用指数期货，二者风险不同 |

简单 L1 加权盘口价可写为 `(ask × bid_size + bid × ask_size) / (bid_size + ask_size)`；价量不同步、数量单位不一致、零数量和异常市场状态时不使用。可以计算某个指标，并不意味着在 IBKR 数据及执行条件下存在可交易优势。
